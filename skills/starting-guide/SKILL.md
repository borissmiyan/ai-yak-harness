# 🚀 Starting Guide: Project Kickoff & Infra Setup Wizard

> **Axiom:** *«Фундамент проекта определяет его надёжность: детерминированный CI, строгая архитектура и безопасность данных с самого первого коммита»*.

### 📦 Фаза 1: Определение типа продукта и платформы (Product DNA)

Перед выбором технологий агент выясняет платформенную специфику проекта:

| Платформа | Ключевые особенности и Hard Invariants | Рекомендуемый базовый стек |
| :--- | :--- | :--- |
| **Telegram Mini App (TMA)** | Обязательный отступ `pt-header-safe` (**96px**) для системных кнопок Telegram; криптографическая проверка `initData` (HMAC-SHA256); тактильный отклик (Haptics); 0ms оффлайн-кэш. | React 19 (Vite) + Tailwind CSS v4 + Dexie.js + Supabase + Motion v12 |
| **Web SaaS / Dashboard** | Адаптивность Desktop/Mobile; быстрый рендеринг таблиц с виртуализацией; ролевой доступ (RBAC); экспорт отчетов (Excel/PDF). | React 19 (Vite / Next.js) + Tailwind CSS v4 + TanStack Table / Virtual + Supabase |
| **Mobile Cross-Platform** | Нативные жесты, `SafeAreaView`, поддержка оффлайн-режима, пуш-уведомления. | React Native / Expo + Tamagui / NativeWind + Supabase / WatermelonDB |
| **Desktop Application** | Локальная файловая система, IPC-безопасность, контекстная изоляция `preload.cjs`, оффлайн-работа. | Electron / Tauri + React 19 + Vite + Dexie.js / SQLite |

**Артефакт фазы:** создание файла `PURPOSE.md` с миссией, целевой аудиторией, ключевыми сущностями и требованиями к SLA.

### 🐙 Фаза 2: Репозиторий, ветки и CI/CD (VCS Architecture)

1. **Выбор платформы контроля версий:**
   - **GitHub (Рекомендуется):** полная интеграция с GitHub Actions, `gh` CLI, Secrets Store, Issues/PRs.
   - **GitLab:** для enterprise self-hosted инсталляций.

2. **Двухконтурная модель веток (Branching Model):**
   - `main` / `master` — **Production**. Защищённая ветка. Деплоится автоматически на прод только при 100% прохождении CI.
   - `dev` — **Staging & Active Development**. Ветка повседневной разработки. Сюда коммитятся все фичи и TDD-шаги.

3. **Инициализация Git и базовая гигиена:**
   ```bash
   git init
   git branch -M dev
   ```
   * Создание защищенного `.gitignore` (гарантированное исключение `.env*`, `.dev.vars`, `dist/`, `node_modules/`, `*.pem`, `*.key`).
   * Настройка Husky: `npx husky init`, создание `.husky/pre-commit` и `.husky/pre-push`.

4. **Batch Push Protocol (Защита от очередей CI):**
   > [!IMPORTANT]
   > Все промежуточные TDD-шаги коммитятся локально за 10–15 секунд. Команда `npm run push:verify` вызывается **СТРОГО ОДИН РАЗ в самом финале задачи**, отправляя всю пачку коммитов за один прогон CI.

### 🗄️ Фаза 3: База данных, Аутентификация и Бэкенд

#### Матрица выбора бэкенда:

| Стек | Когда выбирать | Плюсы | Минусы |
| :--- | :--- | :--- | :--- |
| **Supabase (PostgreSQL)** *(Recommended)* | TMA, веб-приложения, стартапы, оффлайн-первые системы | Встроенные Auth, Row Level Security (RLS), Realtime подписки, авто-генерация типов, PostgREST API | Требует контроля функциональных индексов и RLS InitPlan |
| **Cloudflare Workers + D1 / KV** | Ультра-быстрые глобальные API, боты, микросервисы | 0ms холодный старт, глобальный Edge, низкая стоимость | Ограничения SQLite, отсутствие сложных процедур PL/pgSQL |
| **PostgreSQL (Neon / Hetzner)** | Высоконагруженные OLTP/OLAP сервисы со сложной бизнес-логикой | Полный контроль над сервером и расширениями | Необходимость самостоятельной настройки Auth и API |

#### Обязательные стандарты для Supabase:
- **RLS на 100% таблиц:** Любая таблица создается с `ALTER TABLE table_name ENABLE ROW LEVEL SECURITY;`.
- **Оптимизация RLS InitPlan:** Использование `(select auth.uid())` вместо `auth.uid()`.
- **Функциональные индексы:** Если колонка проверяется через `UPPER(TRIM(col))`, обязателен индекс `CREATE INDEX ON table (UPPER(TRIM(col)))`.
- **Search Path Hygiene:** Все функции с `SECURITY DEFINER` обязаны иметь `SET search_path = public, pg_temp;`.

### 🌐 Фаза 4: Хостинг, CDN и Объектное хранилище (Cloud Infrastructure)

1. **Фронтенд и Edge Хостинг:**
   - **Cloudflare Pages / Workers (Рекомендуется):** Бесплатный неограниченный исходящий трафик, встроенная защита от DDoS, автоматический SSL, глобальное время отклика < 30 мс.
   - **Vercel:** Лучший выбор для SSR/Next.js.

2. **Объектное хранилище файлов (Object Storage):**
   - **Cloudflare R2 (S3-compatible):** 0$ за трафик (Zero Egress Fees). Идеально для медиафайлов, пользовательских документов и автоматических ночных дампов БД.
   - **Supabase Storage:** Удобно для простых аватаров и прямого доступа через RLS.

### 🎨 Фаза 5: Фронтенд, Стек и Дизайн-система

1. **Золотой стек компонентов:**
   - **Сборка:** React 19 + Vite + TypeScript.
   - **Стилизация:** Tailwind CSS v4 (на базе CSS-переменных темы).
   - **Иконки:** Векторный пакет `lucide-react` (полный запрет сырых эмодзи в JSX).
   - **Анимации:** Motion (Framer Motion v12) с оптимизацией под 120fps.
   - **Оффлайн-кэш:** Dexie.js (IndexedDB) с 0ms задержкой чтения.

2. **Геометрические инварианты интерфейса:**
   - Высота интерактивных элементов: строго от **48px (`h-12`)** до **56px (`h-14`)**.
   - Скругления: `rounded-2xl` (squircle, избегать острых или капсульных pill-кнопок).
   - Симметричные отступы: `p-4`, `p-5`, `p-6` (отступы по горизонтали равны отступам по вертикали).

3. **Генерация артефактов дизайн-системы:**
   - `DESIGN-AI.md` (токены, цвета, правила для LLM).
   - `COMPONENTS.md` (реестр во избежание дублирования).
   - `ANTIPATTERNS.md` (база запрещённых антипаттернов).

### 🛡️ Фаза 6: Имплантация AI Yak Harness (Quality Gates)

Перенос и активация пакета проверок из репозитория `borissmiyan/ai-yak-harness`:
1. `scripts/verify-no-test-tampering.mjs` — запрет модификации тестов и добавления зависимостей без явного флага.
2. `scripts/verify-diff-budget.mjs` — ограничение диффа: максимум 450 строк и 10 файлов на коммит.
3. `scripts/verify-component-budget.mjs` — бюджет размера компонентов (150–250 строк, максимум 500).
4. `scripts/verify-no-secrets.mjs` — защита от коммита приватных ключей, токенов и паролей.
5. `scripts/verify-resource-hygiene.mjs` — защита от утечек памяти (таймеры, листнеры, `createObjectURL`).
6. `scripts/verify-supabase-compliance.mjs` — RLS, Search Path, функциональные индексы и N+1 циклы.
7. `scripts/verify-security-antipatterns.mjs` — проверка TMA initData, IDOR и запрет утечки сырых ошибок в UI.
8. `scripts/verify-remote-ci.mjs` — автоматический мониторинг удалённого GitHub Actions CI.
9. Инициализация `.planning/` (`CONTEXT.md` и шаблон `decisions/TEMPLATE.md`).
10. Построение первичного AST-графа: `graphify update .`.

## 👤 Протокол передачи задач человеку (Human Action Handoff)

Когда задача требует действий, которые ИИ технически не может выполнить сам (нет доступа к браузеру, 2FA, ввод платежных данных, генерация закрытых токенов в UI провайдера), агент **ОБЯЗАН выдать стандартизированную карточку**:

```markdown
### 👤 Требуется действие разработчика (Human Action Required)

#### 1. Что нужно сделать:
[Краткое, понятное описание действия в 1-2 предложениях]

#### 2. Пошаговая инструкция:
1. Перейдите по прямой ссылке: [Прямой URL страницы настроек]
2. Нажмите кнопку **«[Название кнопки]»**.
3. Заполните поля:
   - Поле A: `значение`
   - Поле B: `значение`
4. Нажмите **«Сохранить / Create»**.

#### 3. Что скопировать:
- `ПАРАМЕТР_1`: [Где он находится на экране]
- `ПАРАМЕТР_2`: [Где он находится на экране]

#### 4. Что прислать мне в чат:
Скопируйте и пришлите следующие строки:
\`\`\`env
VARIABLE_NAME_1=значение_1
VARIABLE_NAME_2=значение_2
\`\`\`
*(Я автоматически сохраню их в `.env.local` и настрою GitHub Secrets)*.
```

## 📋 Чек-лист готовности проекта к первому релизу (Pre-Flight Gate)

Перед тем как объявить проект инициализированным, агент подтверждает:
- [ ] Репозиторий инициализирован с ветками `dev` и `main`.
- [ ] `.gitignore` защищает все приватные файлы и секреты.
- [ ] Проект компилируется с 0 ошибок: `npm run check` (tsc + linter + vitest).
- [ ] Production-бандл собирается чисто: `npm run build`.
- [ ] Создан начальный архитектурный контекст `.planning/CONTEXT.md` и ADR D-01.
- [ ] Создана дизайн-система `DESIGN-AI.md` и реестр `COMPONENTS.md`.
- [ ] Все pre-commit хуки Husky активны и отрабатывают за < 15 секунд.
- [ ] Удалённый GitHub Actions CI Quality Gate настроен и проверен с кодом выхода 0.
