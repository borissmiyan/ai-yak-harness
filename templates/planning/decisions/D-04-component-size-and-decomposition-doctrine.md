# D-04: TSX Component Architecture, Size Budget (150–250 lines) & Decomposition Doctrine

## Status
Accepted

## Date
2026-10-15

## Context
В крупномасштабных React & TypeScript проектах корпоративного уровня (уровня Vercel, Stripe, Airbnb) существует архитектурный закон: **чем масштабнее проект, тем компактнее должны быть отдельные файлы компонентов**.
Предыдущее наивное ограничение «до 500 строк на файл» воспринималось разработчиками и ИИ-агентами как допустимая целевая норма, что приводило к следующим деструктивным последствиям:
1. **Смешение 4 слоев в одном `.tsx` файле:** типизация, побочные эффекты и стейты (`useState`, `useEffect`, селекторы стора), чистые хелперы/константы и развесистый JSX с классами Tailwind.
2. **AI Attention Drift & Token Inflation:** При превышении 300–400 строк контекстное окно внимания LLM размывается. Нейросеть начинает «забывать» код в начале файла, плодит дубликаты стейтов, забывает закрывать JSX-теги, случайно ломает соседнюю бизнес-логику при правке верстки и тратит в 3-5 раз больше токенов на каждую итерацию.
3. **Merge Conflicts & Непредсказуемые ререндеры:** Огромные файлы вызывают шквал конфликтов слияния в Git и препятствуют точечной React.memo мемоизации.

## Decision
1. **Индустриальная градация размера `.tsx` и `.ts` файлов:**
   - **50–150 чистых строк (Идеал UI-Kit):** Presentational (глупые) компоненты — кнопки, инпуты, карточки, простые модалки. Читаются за 10 секунд без скролла.
   - **150–250 чистых строк (Золотой стандарт Enterprise):** Smart/Container компоненты, виджеты, экраны, сложные формы. Связка данных и верстки.
   - **Хуки `**/use*.ts` (Лимит 150 warn / 250 error):** Предотвращает превращение хуков в помойку бизнес-логики.
   - **300 чистых строк (Желтая зона / Tech Debt):** Сигнал линтера (`max-lines: warn` на 300 строк, `max-lines-per-function: warn` на 200 строк). Компонент перегружен ролями.
   - **500 чистых строк (Красная зона / Hard Emergency Ceiling):** Жесткий аварийный потолок. Блокировка в пре-коммите и CI (`scripts/verify-component-budget.mjs`, ESLint `error` на 500).
2. **3 обязательных правила декомпозиции:**
   - **Правило 1 (Вынос логики в кастомный хук `use<ComponentName>.ts`):** Если в компоненте больше трех `useState`, есть `useEffect` или 4–5 обработчиков событий — логика выносится в хук. В `.tsx` остается одна строчка вызова хука и чистый JSX (-30..50% объема файла).
   - **Правило 2 (Выселение статики и чистых функций):** Любая функция, не зависящая от жизненного цикла React (форматирование, парсинг, константы опций), переносится в `utils.ts`, `constants.ts` или `types.ts`.
   - **Правило 3 (Изоляция тяжелых фрагментов JSX & Колокация стейта):**
     * Логический блок верстки длиннее 40–50 строк (шапка, фильтры, карточка элемента) выносится в отдельный подкомпонент (`FeatureHeader.tsx`, `FeatureFilter.tsx`).
     * **Колокация стейта:** Приватный UI-стейт (например, `searchQuery` фильтра) обязан переехать внутрь дочернего компонента, а не прокидываться сверху, чтобы ввод текста не перерисовывал всю родительскую страницу.
     * **Запрет Barrel-файлов:** Запрещено плодить вложенные `index.ts` внутри папок отдельных компонентов.
3. **Двухуровневый шлюз контроля:**
   - ESLint AST (`configs/eslint.config.harness.js`) предупреждает в IDE в реальном времени и блокирует вложенные компоненты (`react/no-unstable-nested-components`).
   - Скрипт `scripts/verify-component-budget.mjs` детерминированно валидирует Git Index в pre-commit и CI через ESLint JSON. Исключения задаются только в `configs/budget-exceptions.json`.

## Key Invariants
- **TSX Clean Lines Hard Gate:** Ни один новый `.tsx` компонент не может быть закоммичен при объеме свыше 500 чистых строк кода.
- **Hook Clean Lines Hard Gate:** Ни один хук `use*.ts` не может превышать 250 чистых строк кода.
- **No Unstable Nested Components:** Запрещено объявление компонентов внутри тел других компонентов.
- **State Colocation Invariant:** Приватный стейт изолируется в подкомпоненте.
- **No Inline Bypasses:** Исключения регистрируются исключительно через `configs/budget-exceptions.json`.

## Consequences
- **Positive:** Компоненты легко читаются, рендерятся без побочных штормов, а ИИ-агенты работают сфокусированно с минимальным расходом токенов и нулевыми галлюцинациями структуры JSX.
- **Negative / Trade-offs:** Требует дисциплины колокации стейта и создания файлов хуков вместо складирования логики в один файл.
